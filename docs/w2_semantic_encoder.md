# 实验记录：CLAP 语义特征提取模块

日期：2026-09-19 ｜ 对应计划：W2 任务 2（P0）

## 目标

提供两种粒度的 512 维语义向量（全曲级 / 片段级），并带上耗时统计——
第 3 周要评估"把语义向量喂给分离网络值不值"，开销必须可量化。

## 设计

- **实现统一走 LAION 官方 `laion_clap`**。第 2 周已确认 HuggingFace 移植版与官方实现
  的嵌入不在同一个空间（同音频余弦 0.29），移植版零样本 mAP 0.2163，官方 0.3136。
- **全曲级**：均匀取 N 个**长度正好 10 秒**的窗口取平均。不用随机窗口：
  随机窗口会让同一个文件多次编码结果不一致（实测最大差值 2.6e-2）。
- **片段级**：按固定窗口切分，末尾不足一个窗口补零，保证尾巴不丢。
- 读不了的文件（MTT 里有 3 个坏文件）用零向量占位并计数，不让整批任务崩掉。

代码：`src/semantic/clap_encoder.py`

| 可复现性 | 同一文件编两次，最大差值 **0.00e+00** |
| 片段级向量 | 29.3 秒 → 3 个 10 秒片段，形状 (3, 512) |

耗时统计（本机 CPU，i7-13700H）：

| 项目 | 数值 |
|---|---|
| 模型加载 | 4.4 秒 |
| 编码片段数 | 35 |
| 读音频总耗时 | 0.52 秒 |
| 模型前向总耗时 | 5.22 秒 |
| **平均每片段** | **0.149 秒** |

## 结论

1. 模块可用，全曲级与片段级两种粒度都能直接调用。
2. 0.149 秒/片段的 CPU 开销意味着：一首 3 分钟的歌取 3 个窗口约 0.45 秒，
   相对分离本身（GPU 7.5 秒 / CPU 200 秒）可以忽略，**语义向量不会成为流水线瓶颈**。
3. 一个实现细节值得记住：CLAP 内部对超过 10 秒的输入是"随机裁 10 秒"，
   所以窗口切分必须自己保证 ≤10 秒，否则结果不可复现（这次就踩到了）。
