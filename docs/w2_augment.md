# 实验记录：数据增强模块与 3 组消融

日期：2026-09-19 ｜ 对应计划：W2 任务 3（P0）

## 目标

把 5 种波形增强封装成可配置、可插拔的模块，并用 3 组消融回答"增强对微调有没有帮助"。

## 设计

五种增强，全部作用在波形上，**成对作用于 mixture 与 targets**：

| 名称 | 做什么 |
|---|---|
| `gain` 随机增益 | 整体乘 −6 ~ +6 dB 的随机增益 |
| `polarity` 极性反转 | 整体乘 −1 |
| `band_stop` 频带掩蔽 | 用理想带阻把随机一段频率置零 |
| `time_crop` 时间裁剪 | 随机保留一段连续区间，其余置零 |
| `channel_swap` 通道互换 | 左右声道对调 |

关键约束：五种都是同一个线性/掩蔽算子作用在所有轨上，因此
**`mixture == Σ targets` 这条物理关系在增强后依然成立**。这是分离任务最容易写错的地方
（只改混合不改目标 = 喂错标签），必须在单元测试里逐条验证。

代码：`src/data/augment.py`；配置：`configs/augment_default.json`、`configs/augment_off.json`

## 3 组消融

```powershell
# 云端 GPU（每组 300 步，变量只有增强配置）
python scripts/33_augment_ablation.py --steps 300 --lr 1e-4 --batch-size 3 --device cuda
```

| 组 | 增强 | 想回答的问题 |
|---|---|---|
| `none` | 全关 | 对照组 |
| `mask` | 只开频带掩蔽 + 时间裁剪 | "输入有缺失"这一类增强有没有用 |
| `default` | 五种全开 | 完整配置的净效果 |

指标用训练脚本内置的每轮 SI-SDR 验证（训练前 → 训练后），因为 museval 一首要三分钟，
不适合放进短程消融。

### 结果

三组各 300 步、batch 3、lr 1e-4，唯一变量是增强配置；验证用前 3 首测试曲目的中位 SI-SDR。
每组耗时约 16 分钟（RTX A4000）。

| 组 | 增强 | 训练前 | 训练后 | 变化 | Δdrums | Δbass | Δother | Δvocals |
|---|---|---|---|---|---|---|---|---|
| `none` | 全关 | 7.072 | 7.130 | **+0.059** | −0.19 | −0.02 | +0.51 | −0.07 |
| `mask` | 只开掩蔽类 | 7.092 | 7.054 | **−0.038** | −0.17 | +0.01 | +0.27 | −0.26 |
| `default` | 五种全开 | 7.067 | 7.189 | **+0.122** | −0.11 | −0.03 | **+0.71** | −0.08 |

训练损失（末 50 步平均）：

| 组 | 首 50 步 | 末 50 步 |
|---|---|---|
| `none` | 0.0995 | 0.1045 |
| `mask` | 0.0988 | 0.1049 |
| `default` | 0.0973 | **0.1004** |

增强触发次数（`default` 组 300 步）：极性反转 457 次、通道互换 448 次、随机增益 446 次、
频带掩蔽 286 次、时间裁剪 276 次——比例与配置里的概率一致，说明流水线接对了。

## 结论

1. **完整增强 > 无增强 > 只做掩蔽**（+0.122 / +0.059 / −0.038）。完整增强在验证指标上
   比不做增强高 0.063 dB。
2. **收益几乎全部来自"其他"轨**：`default` 组"其他"轨 +0.71，明显高于 `none` 组的 +0.51；
   鼓和人声两组都略有下降。这和第 2 周其它实验的结论一致——"其他"轨是当前最弱、也最有改进空间的一条。
3. **只做掩蔽类增强反而比不做还差**（−0.038）。掩蔽会把输入频谱挖空，
   如果不同时配合增益/极性/通道这些"不损坏信息"的增强，模型只是在学残缺输入，得不偿失。
4. **增强组的训练损失最低**（0.1004 对 0.1045），而它的输入是三种配置里最难的。
   在更难的输入上拟合得更好，符合"增强起正则化作用"的预期。
5. **必须说明的局限**：只有 300 步、3 首验证曲目，噪声量级约 ±0.03 dB（三次"训练前"
   指标本应完全相同，实测 7.067~7.092，差异来自 GPU 非确定性）。所以 +0.122 与 +0.059
   之间的差只有 2 倍噪声，**方向可信、幅度不可过度解读**。要下定论需要更长训练与更多验证曲目。

## 对第 3 周的启示

- 增强配置可以保留（用 `configs/augment_default.json`），但**不要指望它救整体 SDR**；
  真正该配合的是"其他"轨与语义条件分离。
- 只做掩蔽类增强是负面的，第 3 周不要再单独试这一路。

## 备注：关于 mir_eval

计划里原本写的是"集成 mir_eval"。实际实现换成了 **训练中每轮 SI-SDR + 最终 museval**，
理由如下：

- MUSDB 官方评测口径是 `museval` 的 BSS Eval v4（逐帧算完取中位数），
  mir_eval 的 `bss_eval_sources` 是更早的 v3 口径，两者的窗长与聚合方式都不同；
  同一份分离结果用两套库会得出不同的绝对值，混着用会让报告里的数字不可比。
- 训练循环里需要的是"便宜、方向正确"的信号，SI-SDR 只要几秒且无需额外依赖，
  比 mir_eval 更合适。

所以这里是有意偏离计划，而不是漏做；若导师要求，可以补一份 mir_eval 的对照数字。
