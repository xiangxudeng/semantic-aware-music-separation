# Demucs v4（htdemucs）架构拆解

第 2 周任务 1 的前半部分。本文里的**每个数字都是用 `scripts/34_demucs_arch_summary.py`
在真实权重上实测导出的**，不是从论文抄的——论文里的结构描述和代码里的实际实现有出入，
第 3 周要做条件注入，必须知道代码里到底是什么样。

---

## 一、一句话概括

htdemucs 是一个**频域 + 时域双分支**的 U 型网络：两条分支各自下采样到相同的时间分辨率，
在瓶颈处用跨域 Transformer 交换信息，再各自上采样，最后用估计出来的掩蔽去乘原始频谱重建四条音轨。

---

## 二、数据流全景（实测形状）

输入按 2 秒 44.1kHz 立体声（`1×2×88200`）喂进去。注意一个细节：模型在 eval 模式下会先把
输入补齐到训练片段长度 7.8 秒再算，最后再把输出裁回原始长度，所以下面的中间形状都是按 7.8 秒算的。

```
波形 (1, 2, 88200)
 ├─ STFT（nfft=4096, hop=1024, Hann） ─► 幅度谱 (1, 2, 2048, 336)      ← 频域分支
 └─ 原始波形                                                            ← 时域分支

频域分支 encoder（4 层 HEncLayer，频率轴每层 ÷4）
    encoder.0  (1,  48, 512, 336)
    encoder.1  (1,  96, 128, 336)
    encoder.2  (1, 192,  32, 336)
    encoder.3  (1, 384,   8, 336)

时域分支 tencoder（4 层，长度每层 ÷4，最终做到频域帧数的 4 倍）
    tencoder.0 (1,  48, 85995) → tencoder.1 (1,  96, 21499)
    tencoder.2 (1, 192,  5375) → tencoder.3 (1, 384,  1344)

跨域 Transformer（5 层）
    crosstransformer → (1, 512, 8, 336)                                   ← 75% 的参数在这里

频域解码（4 层 HDecLayer，带 skip connection）
    decoder.0 (1, 192, 32, 336) → … → decoder.3 (1, 16, 2048, 336)
时域解码（4 层 HDecLayer）
    … → tdecoder.3 (1, 8, 343980)

掩蔽 + iSTFT ─► 输出 (1, 4, 2, 88200)      （B, 音源数, 通道, 采样点）
```

## 三、逐组件拆解

### 3.1 STFT 前端（`_spec` / `_magnitude`）

- `nfft=4096`、`hop_length=1024`，两者固定为 4 倍关系（代码里有 `assert hl == nfft // 4`）
- 为了对齐两个分支的时间轴，STFT 前会先做反射填充，保证帧数等于 `ceil(长度 / hop)`
- 只把**幅度谱**送进网络，相位不参与学习——最后重建时用混合信号自己的相位（`_mask` 阶段）

### 3.2 双分支编码器

| | 层数 | 通道变化 | 下采样轴 |
|---|---|---|---|
| 频域 encoder | 4 | 48 → 96 → 192 → 384 | 频率轴 ÷4 每层，时间轴不动 |
| 时域 tencoder | 4 | 48 → 96 → 192 → 384 | 只压缩时间轴 |

两条分支的**通道数完全对称**，这样瓶颈处才能直接做跨域注意力。时域分支每层把长度 ÷4，
四层之后正好是频域帧数的 4 倍（1344 对 336），保留更细的时间分辨率。

### 3.3 跨域 Transformer 瓶颈

`crosstransformer` 有 **5 层**，输出 `(1, 512, 8, 336)`。它拿到了整个模型 **75.1% 的参数量
（31.55 M / 41.98 M）**。

这一点对第 3 周很关键：模型的表达能力绝大部分在瓶颈，条件注入如果只加在最外层卷积上，
信息很难影响到真正做决策的部分。

### 3.4 解码器与 skip connection

- 频域 decoder 从 192 通道逐层升回 2048 个频点，最后输出 16 通道（= 4 音源 × 4 个掩蔽分量，见 3.5）
- 时域 tdecoder 输出 8 通道（= 4 音源 × 2 通道）
- 每条 skip connection 都从编码器对应层拉过来，**解码时 `saved.pop(-1)`，是标准的 U 型结构**

### 3.5 掩蔽与逆变换

解码器输出的不是波形，而是**掩蔽**。`_mask(z, m)` 用估计出的掩蔽乘上原始混合的复频谱，
再走 iSTFT 拿回波形。好处是相位直接沿用混合信号的相位，避开了"相位重建"这个难点。

模型里还有 `wiener_iters` 这个后处理开关，但**实测取值为 0**，也就是预训练权重默认不做维纳滤波。
所以要复现论文里的 SDR，不需要额外开这个。

### 3.6 归一化

前向里有两次**逐曲目归一化**：频域分支按幅度谱的均值方差归一，时域分支按波形的均值方差归一，
最后再把输出还原回去。微调脚本必须跟这条链路保持一致（`scripts/20_finetune_demucs.py` 里就是这么写的），
否则训练和推理的输入分布会对不上。

## 四、参数量分布（实测）

| 子模块 | 参数量 | 占比 |
|---|---|---|
| **crosstransformer** | **31.55 M** | **75.1%** |
| decoder（频域） | 4.56 M | 10.9% |
| tdecoder（时域） | 2.21 M | 5.3% |
| encoder（频域） | 1.42 M | 3.4% |
| tencoder（时域） | 1.42 M | 3.4% |
| channel_upsampler / downsampler（各 ×2） | 0.79 M | 1.9% |
| freq_emb | 0.02 M | 0.1% |
| **合计** | **41.98 M** | 100% |

编码器逐层参数量（频域）：9.9 K → 68.5 K → 270.7 K → 1.08 M，**参数量集中在最深层**，
浅层非常轻。这也是为什么"冻结浅层、只训深层"这种做法在这个结构上省不了多少显存。

## 五、对第 3 周"语义条件分离"的直接结论

1. **可注入点与通道数（实测）**

   | 注入点 | 通道数 | 张量形状 |
   |---|---|---|
   | encoder.0 | 48 | (B, 48, 512, 336) |
   | encoder.1 | 96 | (B, 96, 128, 336) |
   | encoder.2 | 192 | (B, 192, 32, 336) |
   | encoder.3 | 384 | (B, 384, 8, 336) |
   | decoder.0 | 192 | (B, 192, 32, 336) |
   | decoder.3 | 16 | (B, 16, 2048, 336) |

   时域分支的通道数和频域一致，但长度是 4 倍，两个分支要各配一个 FiLM，不能共用。

2. **注入位置的选择有依据了**：既然 75% 的参数在瓶颈，条件信息至少要能影响到
   `crosstransformer` 附近；只在最浅层注入等于让条件走完整个网络才能生效。
   第 3 周的对比实验就按"只在编码器 / 只在解码器 / 两者都加"三档来做。

3. **FiLM 的开销可以算准**：以 512 维条件注入 384 通道为例，`512×384×2 ≈ 393 K` 参数；
   注入两个点合计约 593 K，占主干的 **1.41%**（这个数在 `scripts/30_film_unit_test.py` 里实测）。
   相比全参数微调（42 M 全部要更新），这是非常小的改动。

## 七、与六轨版（htdemucs_6s）的差异

| | htdemucs（四轨） | htdemucs_6s（六轨） |
|---|---|---|
| 输出音源 | drums / bass / other / vocals | 上面四条 + guitar / piano |
| 输出张量 | (B, 4, 2, T) | (B, 6, 2, T) |
| MUSDB18 测试集 SDR | **8.86 dB** | 6.93 dB |
| 合并 guitar+piano+other 后 | — | 8.38 dB |

**结论**：六轨版在 MUSDB18 上"其他"轨崩塌（0.17 dB）是**标注口径造成的假象**——它把吉他、钢琴
单独拆走，而 MUSDB18 的参考标注里这两类仍算在 other 里。即使按公平口径（三轨相加）比较，
六轨仍比四轨低 0.48 dB，那是模型容量被分散到六条轨的真实代价。

按导师"以结果最好的为准"的要求，**项目统一采用四轨（htdemucs）口径**。
